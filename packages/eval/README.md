# Telegram summary eval

This package runs reproducible representation experiments against Ollama. Each
case has one canonical `messages.json`; JSONL, pipe, and natural-language inputs
are generated by code so an A/B test cannot accidentally change chat content.

`pipe-v2` is a versioned chat DSL rather than a bare delimiter convention. Its
grammar gives the model explicit message IDs, reply edges, media kinds, JSON
string escaping, and thread-reconstruction semantics. Compare it with the old
pipe control using `pipe-language-v2`.

`pipe-v3` is the compact follow-up. It keeps the reply graph but explicitly
separates structure from salience and defines resolved questions. Compare it
with the original control using `pipe-language-v3`.

The default representation experiment uses four curated, author-pseudonymized
cases imported from the real Telegram collector. The five small synthetic cases
remain available through `synthetic-regressions-v1` for focused regressions.

## Run

Ollama must be running and able to access the models named by the experiment:

```bash
pnpm eval --experiment representation-v1
```

Set `OLLAMA_BASE_URL=https://ollama.com` for direct Cloud API access. The eval
runner loads `OLLAMA_API_KEY` from the workspace `.env` and sends it as a Bearer
token. Direct API model tags omit the local `-cloud` suffix. Existing runs are resumed. Pass
`--overwrite` to intentionally replace runs with the same
experiment/case/model/representation/reasoning/seed path.

Validate fixtures and show the planned run count without contacting Ollama:

```bash
pnpm eval --experiment representation-v1 --validate-only
```

Every raw run is stored under `results/<experiment>/.../seed-N.json`, including
the final text, thinking text, hashes, strict parse result, timing, and metrics.
The experiment directory also receives `results.csv` and `aggregate.csv`.

## Reasoning frontier

`reasoning-frontier-v1` measures the same four real chats with the same
`pipe-v3` prompt at Ollama's `low`, `medium`, and `high` reasoning levels,
with three seeds per cell:

```bash
pnpm eval --experiment reasoning-frontier-v1
```

The native Ollama API does not expose a separate hard reasoning-token budget.
For GPT-OSS, the supported control is a reasoning level, and thinking cannot be
fully disabled. The experiment therefore records the observed thinking and
final-text token counts with the model's Harmony tokenizer instead of treating
the level labels as token counts.

`frontier.csv` reports a Pareto table of quality dimensions, tokens, latency,
and run success. It deliberately does not collapse them into one quality
score. `reasoning-paired.csv` compares every target level with `low` separately
for every metric and produces a 95% cluster-bootstrap interval over cases.

## Behavioral evaluation

`behavioral-v1` treats each chat as a family of related executions rather than
an isolated benchmark row. The runner derives controlled variants from the
canonical messages:

- `identity-replay` sends the byte-identical prompt again to measure the
  model/provider test-retest noise floor even when the seed is fixed;
- `rename-users` replaces participant names with stable `U1`, `U2`, ... aliases;
- `shift-timestamps` moves every timestamp by the same amount while preserving
  order and intervals.

Both are semantic invariants: the matched content-unit and thread sets should
remain stable. `paired.csv` reports target-minus-baseline deltas plus claim-set
and thread-set Jaccard invariance. Its 95% interval is a deterministic paired
cluster bootstrap over cases: seeds are averaged inside a case before cases are
resampled, so repeated stochastic runs do not masquerade as independent chats.
Rows marked `transformation-vs-replay` compare a transformed input with the
byte-identical replay, exposing sensitivity beyond the provider's noise floor.

```bash
pnpm eval --experiment behavioral-v1
```

`stages.csv` keeps the contracts separate:

- extractor: event recall/precision, speaker attribution, evidence validity,
  and relation integrity;
- reducer: lifecycle invariant violations;
- projection: recall, precision, forbidden promotion, and noise retention;
- end-to-end: latency, calls, and semantic amplification.

Extractor event recall/precision currently align event evidence with curated
content units. They are an explicit proxy until cases contain a separately
annotated event log. `extractor-variance.csv` measures pairwise event-set and
edge-set Jaccard across repeated runs. Reducer correctness is tested without an
LLM by replaying synthetic event logs into exact state snapshots.

Experiments may set `pipelines` to `direct`, `deterministic-shell`, or both.
The direct path asks for the final projection in one call. The shell path asks
only for discourse events, reduces them deterministically, then projects the
state. Both record `semanticAmplification = semanticInterpretations /
sourceMessageWindows`; it is 1 for either one-call path and grows when another
independent semantic pass is introduced.

The stronger-model screening is intentionally split into validateable configs:

```bash
pnpm eval --experiment qwen397-smoke --validate-only
pnpm eval --experiment qwen397-screening-v1 --validate-only
pnpm eval --experiment deepseek-v4-screening-v1 --validate-only
```

The repository currently has 13 adversarial/real cases, so the full Qwen grid
contains 130 calls (13 cases × 2 pipelines × 5 seeds) and DeepSeek contains 78.
Run the one-call Qwen smoke before authorizing either paid grid.

Mutation experiments declare a baseline case, a minimally changed mutant, and
expected content-unit/category transitions. `mutations.csv` reports how often
the baseline passed, the mutant passed, and both sides crossed the intended
decision boundary in the same seed. Run the first question-to-assertion probe:

```bash
pnpm eval --experiment mutations-v1
```

## Independent thread reconstruction

Thread reconstruction is also executable as a separate model task. It receives
the serialized messages but is explicitly forbidden to summarize, rank, or
compress them. Its output is only message-ID clusters plus unassigned noise.

```bash
pnpm eval:reconstruct --experiment reconstruction-interleaving-v1
```

The reconstruction report measures message coverage, duplicate/unknown
assignments, pairwise clustering precision and recall, major-thread recall, and
best-cluster Jaccard. Gold thread membership is currently derived from the
union of curated claim evidence for each thread, so the metric covers annotated
content units rather than every conversational message.

`interleaving-v1` uses hidden `fixtureThread` annotations that serializers never
expose. `interleave-threads` changes a grouped `A1 A2 B1 B2` conversation into
`A1 B1 A2 B2`, retains reply edges, and reassigns chronological timestamps. The
same relation can therefore be measured both end-to-end and at reconstruction.

## QA factuality

QA factuality is independent of the finite gold claim set. For each generated
claim or decision, the judge creates a diagnostic question, answers it from the
candidate, answers it independently from the cited source messages, and labels
the answer relation and grounding verdict.

```bash
pnpm eval:factuality --experiment factuality-v1
```

The experiment includes a `rotated-evidence` negative control: claim texts stay
unchanged while citations are cyclically taken from other claims. This checks
that a high supported rate is not merely judge acquiescence. Raw questions,
both answers, verdicts, explanations, and telemetry remain in each run file.
The current experiment uses the same model family for generation and judging;
cross-model judges and human calibration are still needed before treating the
score as an unbiased factuality estimate.

## Refresh real cases

Selections live in `collector-cases.json`. Regenerate their canonical messages
and provenance from the local collector with:

```bash
pnpm --filter @microsonya/eval import:collector
```

An alternate collector path can be passed as the final argument. Import assigns
case-local participant aliases, reindexes messages from 1, remaps internal reply
links, and records source IDs plus out-of-range replies in `provenance.json`.
Hand-curated `gold.json` files are never overwritten.

## Case contract

Create `cases/<case-name>/messages.json` and `gold.json`. Gold is a semantic case
specification: weighted threads and claims with stable source message IDs,
forbidden literalizations, decisions, open questions, and optional noise message
IDs. It is deliberately not a single expected summary.

Model output is parsed with `JSON.parse` and validated without repair. Markdown
fences, partial objects, and schema violations are recorded as parse failures.

## Metric boundary

The MVP scorer is deterministic. It aligns generated and gold claims one-to-one
through cited evidence IDs, then reports major-thread recall, weighted claim
recall, `goldClaimPrecision`, evidence precision, forbidden rate, false open
question rate, and noise retention. `goldClaimPrecision` is intentionally named:
it is precision against the finite gold claim set, not a factuality judgment.
A separate claim-vs-cited-messages judge is still required for factual precision
on valid claims absent from gold.
